## FINDING 12: Existence traversal must both SKIP and TRAVERSE OPTIMIZES when a constraint is only satisfiable via an optimizer; bootstrap with no Gen-0 base case
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
Query: 'Can I build a lithium battery in 1975 Chile?' The Battery→Lithium edge carries purity > 99.9% (TB-019). Raw Chilean brine lithium is ~99%; the only way to pass the constraint is the Modifier Stack pulling in the 'molten-salt electrolytic refining' process via its OPTIMIZES edge (ADR-0004: 'optimization paths raise purity'). But this is an EXISTENCE query, and ADR-0006 says existence traversal skips OPTIMIZES edges entirely — that skip is the cycle-breaker. Sharper version, the master lead screw: 'Precision Lathe' requires Lead Screw with pitch_error < 10um; the only optimizer providing that is 'screw-cutting on a precision lathe' OPTIMIZES Lead Screw, a process whose component is the Precision Lathe itself. The cycle is legal (it passes through OPTIMIZES, so the ADR-0013 circuit breaker waves it through), but Gen-0 output — a hand-filed screw at ~100um — fails the optimizer's own input constraint, so Temporal Leveling's 'Gen-0 primitive output builds the optimizer' recursion has no base case. Historically this WAS built (Maudslay, successive approximation), so any 'unrealized' answer is wrong, and any naive answer that ignores the constraint resurrects the vacuum-tube iPhone.

### Claimed failure
ADR-0006 (existence skips OPTIMIZES) directly contradicts ADR-0003 + ADR-0004 (constraints are evaluated DURING existence traversal, and are satisfied only by traversing OPTIMIZES paths / stacking optimizer processes). No ADR defines the composed mode: whether the Modifier Stack may re-enter OPTIMIZES subgraphs inside an existence solve, whether the invoked optimizer's own existence and input constraints are checked, and what cycle/termination rule governs that re-entry. Temporal Leveling (ADR-0006, TB-002) answers only the case where unoptimized Gen-0 output satisfies the optimizer's inputs; when the optimizer's input constraint demands the very attribute only the optimizer provides, the mechanism is silent — the solver either non-terminates, falsely reports REALIZED (skipping the constraint), or falsely reports unrealized (wrongness, violating ADR-0015 — the thing was historically built). TB-002 and TB-019 each cover one half; their composition is covered nowhere.

### Verifier adjudication (full)
The headline 'direct contradiction' between ADR-0006 and ADR-0003/0004 is a misreading, and all three claimed failure modes (non-termination, false REALIZED, wrongness-via-unrealized) are refuted — but one solver rule is genuinely unwritten. Refutations: (1) No contradiction: ADR-0006's skip rule defines what counts as an existence DEPENDENCY — 'if it optimizes something then it's not necessary to make it' — i.e., an OPTIMIZES edge never appears as a required parent in the support tree. It does not forbid the solver from CONSULTING optimizer processes to satisfy attribute constraints; that consultation is the Modifier Stack (ADR-0004: 'specific requirements like purity are satisfied by optimization paths, never variant nodes'), and ADR-0003 mandates constraint evaluation DURING traversal. Decisively, TB-019 — marked Solved — is already the composed case: battery-grade purity is an existence-relevant consumer constraint answered by 'ADR-0005 + ADR-0004 (optimization paths raise purity).' If the composition were illegal in existence solves, TB-019 could not be Solved. The 1975-Chile query is TB-019 with a date, plus the ordinary check that the molten-salt refining process node is itself REALIZED at (1975, Chile) — which Temporal Leveling presupposes ('Gen-0 output BUILDS the optimizer' is precisely an optimizer-availability gate). (2) False-REALIZED is impossible: constraints are never skipped (ADR-0003); the skip applies to OPTIMIZES edges as dependencies, not to constraint checks — the vacuum-tube iPhone stays dead. (3) The Maudslay lead screw: the cycle Lathe→process→OPTIMIZES→screw→Lathe is legal (ADR-0006/0013) and existence-cut at the OPTIMIZES edge; the historically-attested Gen-0 bootstrap that violates the stated pitch_error constraint is exactly the TB-017 shape ('a historical one-off violates the requirement; reality wins, but the rule must survive'), covered by ADR-0008: record the attested fact as a RequirementOverride/LCA-widening on the first lathe (or, more faithfully, as the refinement chain history actually was — Maudslay-class lathe with looser screw constraint IS_REFINEMENT_OF-ancestor of the precision lathe, with requirement inheritance tightening down the chain). With that fact recorded, Temporal Leveling has its base case and Gen-1+ resolves normally. (4) If nobody has recorded the bootstrap fact yet, the solver returns unrealized — and TB-042(c) explicitly rules that outcome incompleteness, not wrongness: a current_truth node with no valid support path IS the missing-node detector and becomes a bounty localizing exactly the missing override/intermediate lathe ('the same bounty mechanic as iPhone has no path through battery'). ADR-0015 is satisfied by the design's own doctrine. What is genuinely missing: no document states the composed-mode evaluation rule the refutation relies on — that a Modifier-Stack invocation inside an existence solve is itself a realization check of the optimizer process at the query's (time, place), evaluated generation-indexed (generation g may use only attribute states achievable at g−1, with the OPTIMIZES-skip applying inside the re-entered subgraph), terminating by Temporal Leveling's monotone fixpoint (each generation only adds realizations/attribute gains, so iteration to a fixpoint cannot loop). ADR-0006 defines Temporal Leveling only for the case TB-002 covers; ADR-0017's consequences show the project consciously defers solver evaluation details to Phase 4, but this one sentence is load-bearing for TB-002×TB-019 composition and should be pinned now — as an ADR-0006 amendment plus a new TB case for the self-referential-optimizer bootstrap.

## FINDING 13: RequirementExpr leaf referencing an EXCLUDED inherited edge has no defined value
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
The GoPro HERO family root (TB-006 world) carries hard edges to Image Sensor, Battery, GPS Module, plus an authored expression AND(edge_sensor, edge_battery, edge_GPS, OR(edge_microSD, edge_internal_storage)) — the OR forced the expression to exist, and per ADR-0017 it must then reference the hard edges too or they'd be double-counted by the implicit-AND rule. GoPro 12 records EXCLUDE(edge_GPS) with justification 'shipped without GPS' (exactly the ADR-0019 scattered-exception mechanism TB-006 prescribes). Now the solver evaluates GoPro 12's inherited expression, which contains a leaf the override says does not apply. If excluded-leaf = FALSE: the AND fails and GoPro 12 is unbuildable/unrealized — wrong, exclusion means 'does not need it', not 'requirement unmet'. If excluded-leaf = TRUE: correct here, but wrong in the dual case — a family root with OR(edge_GPS, edge_GLONASS) where an instance excludes edge_GPS because it has NO positioning at all now evaluates the OR as vacuously satisfied. If the leaf is pruned and the tree simplified: OR(edge_GPS, edge_GLONASS) minus GPS collapses to require GLONASS — wrong for the no-positioning instance, since the exclusion record cannot say whether the intent was 'this branch doesn't apply' or 'this whole alternative-group doesn't apply'.

### Claimed failure
ADR-0019 defines inheritance only as set algebra ('own edges UNION inherited edges MINUS exclusions') over edge SETS; ADR-0017 defines expressions over edge-ID leaves. Their composition — how an EXCLUDE override rewrites an inherited expression that references the excluded edge, and whether the family's expression tree is even inherited by instances at all — is defined nowhere. This is NOT the deferred tri-state item in ADR-0017's consequences (that covers UNKNOWN edges under graceful ignorance/stubs); an excluded edge is known-inapplicable, a fourth state with no semantics. TB-034 solved exclusion only against the default AND-of-all-hard-edges case. Since exclusion intent is not recorded at branch-vs-group granularity, no uniform evaluation rule exists that avoids asserting a falsehood — a direct ADR-0015 prime-directive violation reachable by composing two Accepted mechanisms.

### Verifier adjudication (full)
The finding's central overclaim — 'no uniform evaluation rule exists that avoids asserting a falsehood' — is refutable. ADR-0019's InheritanceOverride is per-edge {family_edge_id, kind, justification}, so branch-vs-group intent IS recordable at the needed granularity: an instance with no positioning at all excludes BOTH edge_GPS and edge_GLONASS. A prune-and-collapse rule (excluded leaf removed from the inherited tree; a connective whose children are ALL removed is itself removed — never evaluated as a boolean constant) handles every case in the scenario: (1) GoPro 12's AND(sensor, battery, GPS, OR(storage)) drops the GPS conjunct, leaving the correct requirement; (2) the no-positioning instance that excludes both alternatives sees the whole OR vanish, correct; (3) the half-recorded state (only edge_GPS excluded) leaves OR(GLONASS) standing as an inherited-UNASSERTED fact, which ADR-0019 §3 requires to render as a labeled presumption — 'an unrecorded exception renders as a labeled presumption — incompleteness, never a false assertion' — healed by recording the second exclusion (a resolution increase). So no falsehood is asserted under any of the three cases, satisfying ADR-0015. HOWEVER, the finding is right that this rule is written nowhere: ADR-0019's solver consequence is pure set algebra ('own edges ∪ inherited edges − exclusions'); ADR-0017 never mentions expression inheritance at all (ARCHITECTURE §2 speaks only of inheriting requirement EDGES via getRecursiveRequirements); and ADR-0017's deferred tri-state item explicitly covers UNKNOWN edges under graceful ignorance, not known-inapplicable ones — the finding is correct that excluded is a distinct state. TB-034 indeed exercised exclusion only against implicit-AND family edges (camera, WiFi), never against an authored tree. The missing rule, precisely: 'Instances inherit the family root's RequirementExpr with leaf edge-IDs mapped through the override set; an EXCLUDE prunes its leaf; a connective whose children are all pruned is pruned recursively (vacuous, not TRUE/FALSE); surviving inherited structure not asserted at the instance carries presumption status per ADR-0019 §3.' One sentence in ADR-0019 (or a superseding note on ADR-0017) closes it; the composition is otherwise already forced by existing mechanisms.

## FINDING 14: Additive specialization + implicit-AND silently destroys authored OR alternatives
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
A Hydrogenation Process node carries TB-021's canonical expression OR(edge_platinum, AND(edge_palladium, edge_heat)). Two years later a materials contributor, correctly following ADR-0020, specializes the platinum edge: adds 'Platinum Catalyst Mesh' at truth-granularity, and the linter (ADR-0021) marks edge_platinum shadowed_by the finer edge — 'purely additive, never a correction'. But the finer edge is a new hard dependency edge NOT referenced by the existing expression, so ADR-0017's rule 'edges not referenced by an existing expression are implicitly ANDed in' fires: the effective requirement becomes AND(edge_platinum_mesh, OR(edge_platinum, AND(edge_palladium, edge_heat))). The palladium+heat alternative — the whole point of TB-021 — is dead: the node now unconditionally requires platinum. A refinery that was buildable via the palladium route solves as unrealized. Worse, run TB-037's permutation test: if the OR expression had been authored AFTER the specialization, the finer edge would sit inside the OR and the node stays satisfiable — same facts, different insertion order, different solve result.

### Claimed failure
Three-way interaction with no owner: ADR-0017's implicit-AND default assumes new edges arrive through the Componentize wizard (which asks 'alternative or additional?'), but ADR-0020 specialization and the ADR-0021 shadowing linter add covering edges through a path that writes shadow records and never touches, or even inspects, the consumer's RequirementExpr. ADR-0021 §3 defines shadow semantics for counting/truth/rendering queries but says nothing about expression leaves or the implicit-AND set (should shadowed edges' covering edges be exempt from implicit-AND? should leaves be rewritten to the covering edges? — silent). Result: 'adding information only unlocks' — the monotonicity ADR-0017 itself cites as the safety foundation — is violated (a resolution increase LOCKS a previously satisfiable node), and ADR-0023's pinned insertion-order-independence invariant is broken, since the solve outcome depends on whether the expression or the finer edge was authored first. TB-025/TB-035 cover shadowing without expressions; TB-021 covers expressions without shadowing; the composition is covered nowhere.

### Verifier adjudication (full)
Two of the finding's three claims fall to scrutiny; one survives. First, the ADR-0023 order-independence violation is illusory: the pinned invariant ('any sequence of true additions converges to the same effective graph regardless of order,' ADR-0023 §2, TB-037 permutation test) quantifies over permutations of the SAME fact set. The scenario's divergence compares two DIFFERENT fact sets — an expression whose leaves reference edge_platinum vs. a differently-authored expression referencing edge_platinum_mesh. Permute the actual facts (the TB-021 expression, four edges, one shadow record) in any order and the effective graph converges identically both times. Second, the failure is not 'covered nowhere' — the data needed to evaluate correctly already exists: ADR-0021's shadowed_by record states precisely that edge_platinum_mesh covers edge_platinum's claim, and ADR-0021 §2's Specialize flow plus the linter write that record through reviewed lanes. But the surviving claim is genuine: ADR-0017's rule 'edges not referenced by an existing expression are implicitly ANDed in' fires on the mesh edge, and ADR-0021 §3's query-semantics table (counting: skip; truth: keep; rendering: zoom-dependent) is silent on the two things that matter here — whether covering edges join the implicit-AND set, and how expression leaves referencing shadowed edges evaluate. ADR-0017's own safety argument ('adding information only unlocks') is violated: the effective requirement becomes AND(mesh, OR(platinum, AND(palladium, heat))), the palladium route solves unrealized, and a resolution increase has locked a satisfiable node — wrongness under ADR-0015, reached by two individually-documented edits (the Componentize wizard's 'alternative or additional?' question never runs on the Specialize path). The missing rule, precisely: 'An edge that appears in another edge's shadowed_by list is EXEMPT from ADR-0017's implicit-AND set; for expression evaluation, a leaf referencing a shadowed edge is satisfied by that edge OR any of its covering edges.' This is a one-row extension of ADR-0021 §3's per-query-type semantics table, evaluable from existing derived metadata, and restores both monotonicity and TB-021's alternative under every authoring history.

## FINDING 15: Conditionality computation ignores constraint pruning (false 'unconditional' via a pruned OR branch)
**Severity claimed:** medium · **Verdict:** HANDLED

### Scenario
Node 'Lossless Urban Transmission Line' has expression OR(edge_RT_superconductor_cable, edge_HTS_LN2_cable). The room-temp superconductor is validity=hypothetical (TB-041's exact node); the HTS liquid-nitrogen branch is current_truth and REALIZED — but the consumer edge carries the constraint cooling_energy_overhead < 1%, which every LN2 system fails (that constraint is WHY the node sits in the superconductor's pre-built child tree). Query 1, TB-041's signature 'what unlocks if RT superconductivity lands?': conditionality is computed as 'does any path in the requirement expression avoid hypothetical nodes?' (TB-041 answer, ADR-0017 OR + ADR-0026) — the HTS branch avoids them, so the node is classified UNCONDITIONAL and is absent from the unlock cascade. Query 2, node state (ADR-0002/0003): constraint pruning kills the HTS branch, the hypothetical branch is blocked by TB-041's validity rule, every path dies — unrealized. The graph simultaneously answers 'this does not depend on the RT superconductor' and 'this is buildable by no path that avoids it'; the impact-analysis ('how scary if RH/superconductor falls') undercounts the subtree for the same reason.

### Claimed failure
The conditionality entailment as documented (TB-041, restated in ARCHITECTURE §6) is defined purely over the expression tree's hypothetical-node avoidance and never composes with ADR-0003 constraint pruning; no ADR specifies whether pruning runs before the avoidance check. If it doesn't, the documented formula returns a wrong answer (a false 'unconditional' — wrongness, not incompleteness, violating ADR-0015) and the unlock cascade and conjecture impact analysis (TB-041/TB-042 machinery) silently omit exactly the nodes whose only surviving support is the hypothetical branch. TB-041 defined the parentless-magic-box guard for this failure class but only against graceful-ignorance defaults; the constraint-pruned-branch route to the same false unlock is unhandled.

### Verifier adjudication (full)
The finding manufactures the contradiction by assuming 'does any proof path in the requirement expression avoid hypothetical nodes?' means a syntactic expression-branch walk that skips the rest of solver semantics. No documented text supports that reading, and three mechanisms independently close it. (1) 'Path' has exactly one definition in this design — a solver path — and ADR-0003 makes constraint evaluation constitutive of traversal, not an optional pass: 'the solver must evaluate constraints during traversal' (ADR-0003 consequences), 'if constraints eliminate every path, the node becomes unrealized.' A constraint-pruned HTS/LN2 branch (cooling_energy_overhead < 1% fails) therefore contributes NO path; a branch that yields no path cannot witness unconditionality. The formula's own wording — avoid hypothetical NODES, plural — already implies recursive traversal into supporting subgraph, i.e., a full solve, not a one-level expression check; the TB-041 phrasing describes that solve for the mathematics case, where edges carry no attribute constraints so expression-branch and path coincide. (2) The signature query the finding attacks ('what unlocks if RT superconductivity lands?') is defined in TB-041 as 'one validity flip' — an ADR-0026 entailment recomputation. Walk it: before the flip, state computation (ADR-0002: computed from Time+Location+Node) prunes the HTS branch (ADR-0003) and blocks the hypothetical branch (TB-041's validity rule) → unrealized; after the flip, the RT branch realizes → REALIZED; the state diff contains the node. The unlock cascade gets the right answer by construction, because it is a state diff and state computation includes pruning — no separate 'conditionality classifier' sits in that path. (3) Even granting a naive implementation that walked only the expression tree, the design already contains the authoritative tie-breaker the finding says is missing: ADR-0026 §4 — derived values 'must always be recomputable from ground facts, and recomputation always wins a disagreement. A cache that can win is illegal stored inference.' A shorthand conditionality formula that disagrees with full recomputation is by documented rule non-authoritative. The finding's Query 2 result (unrealized, all paths dead) is not the pathology — it is TB-042's bounty state working as designed; under the correct path semantics the classifier returns CONDITIONAL, so the 'simultaneous contradiction' never obtains. Implementation discipline is required (as everywhere), but no rule is missing: the composition ADR-0002 + ADR-0003 + ADR-0026 + TB-041's flip-based cascade already forces the right answer.
