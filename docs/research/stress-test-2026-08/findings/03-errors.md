## FINDING 9: A verifier model is retroactively found systematically wrong; mass demotion has no fact type
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
2029: the L3 machine verifier 'verifier-2028-11' is discovered (via spot audit) to confirm any citation whose abstract shares surface keywords with the claim — a classic LLM verifier failure. ~40,000 claims across the metallurgy and pharma subtrees sit at L3 on citations that do not support them; several thousand climbed to L4/L5 because human reviewers, anchored by the green machine-check badge, confirmed quickly — the exact rubber-stamping ADR-0029 §3 says must never happen but has no mechanism to prevent. The project now needs to demote everything that verifier touched.

### Claimed failure
ADR-0032 §2 makes demotion automatic ONLY through two fact types: source-retraction facts (per source) and upheld challenges (per claim). There is no fact type for 'invalidate all verification events by verifier model X / pipeline P during window W.' The L3 events are recorded facts, and ADR-0034 §5 forbids editing them (append-only record time), so the ladder keeps computing L3+ for all 40,000 claims until each is individually challenged — no batch semantics, no queue, no owner. ADR-0029 §4 handles a discredited pipeline only prospectively ('loses standing' for future edits) and is silent on its existing corpus. The interaction makes it worse: ADR-0033's confidence formula counts verification events as positive evidence, so the poisoned events keep inflating confidence scores graph-wide, and the formula is only contestable 'as a whole' — it cannot express 'events from this verifier version count as zero' because that predicate has no fact to read. TB-044 covers retracted sources and hallucinated citations caught AT the L2→L3 gate; a systematically broken gate itself is uncovered.

### Verifier adjudication (full)
The finding's two structural claims invert the design, but its narrow gap is real. First, append-only does not block cleanup — ADR-0034 §5 defines cleanup AS appending: 'even corrections are new records.' Nothing needs editing; you append a discreditation fact and every computed view changes. Second, 'the predicate has no fact to read' is false: ADR-0032 §1 records verifier model+version+run as a fact on EVERY L3 event, and ADR-0034 §2 states these are versioned precisely so computations can be scoped by them — the poisoned corpus is one query over existing facts. Third, there are no 40,000 stored L3s to chase: levels are computed-never-stored (ADR-0032 §2), so a single new fact read by the level function demotes all matching claims instantly — the exact mechanism TB-044 already proves for retracted sources ('no cleanup crew, no stale confidence'). Fourth, the 'no batch semantics, no queue, no owner' complaint dissolves post-demotion: claims fall to L2 (cited, unchecked — not red), where ADR-0032 §6's standing economic pipeline (machine verification 'pennies per claim, infinitely parallel') re-verifies them with a fixed verifier; the batch IS the computed demotion, the queue IS the existing L2→L3 game. Fifth, ADR-0033 §3 is not helpless: the formula is versioned and openly amendable as a whole, a change 'instantly re-scores the entire graph,' and per-event verifier identity gives it the input it needs. The rubber-stamped L4/L5s demote to genuine-human-confirmation levels and remain individually challengeable (demotion outranks locks, ADR-0032 §1/ADR-0015), with ADR-0034 diffs keeping papers honestly aged. The genuine gap: ADR-0032 §2's enumerated demotion-triggering fact types are source-retractions (per source) and upheld challenges (per claim) only; ADR-0029 §4's pipeline standing is not stated to feed the level computation retroactively. The missing small rule: add one fact type — 'verification-event discreditation': an appended, citable fact (scope: verifier model+version or pipeline identity, optional record-time window, source: the audit) that the level function and confidence formula exclude matching verification events on, exactly parallel to source-retraction facts. Everything downstream — instant graph-wide demotion, re-scoring, re-verification, as-of reproducibility — is existing machinery, so this is one fact type slotting into a proven pattern, not a redesign. PARTIAL.

## FINDING 11: Two individually-valid ChangeRequests jointly violate a circuit-breaker invariant; post-merge enforcement undefined
**Severity claimed:** medium · **Verdict:** PARTIAL

### Scenario
Agent swarm, 2029: agent P proposes 'Haber Process → ENABLES → Industrial Catalysis Research' (CR-1); minutes later agent Q, working the other rabbit hole, proposes 'Industrial Catalysis Research → ENABLES → Haber Process' (CR-2). Each CR is validated in its shadow branch against a master that lacks the other edge — the ADR-0013 cycle breaker passes both, three human vouchers approve each in good faith, and ADR-0031's commutative set-union merges both (different objects, no write conflict, so 'true conflicts route to review' never triggers). Master now contains a non-OPTIMIZES cycle — a state the circuit breaker is defined to auto-reject.

### Claimed failure
ADR-0013's breakers are specified as admission-time checks ('auto-reject cycles'); ADR-0029 §2 and ADR-0031 §2 deliberately make merges commutative and conflict-free for swarm throughput, leaning on ADR-0023 order-independence — but order-independence guarantees convergence of STATE, not preservation of INVARIANTS, and jointly-invalid pairs are invisible to per-CR validation (classic TOCTOU at swarm speed). Once the forbidden state is in master: auto-reject cannot fire (both are merged), no ADR defines which CR is the victim (both are 3-vouched, good-faith, individually true — one edge may even be the correct direction), and the ADR-0013 penalty rule 'vouching for vandalism costs reputation' has no defined answer for six reviewers who each vouched for an individually-valid edit. Recovery falls back to the Finding-3 rollback hole. Same shape applies to the mass-orphaning breaker (two CRs each re-parent half the children). No TB case covers post-merge invariant violation.

### Verifier adjudication (full)
Most of the claimed catastrophe is refuted by composition, but one small rule is genuinely unwritten. What IS covered: (1) The post-merge cycle does not corrupt or crash anything. Cycle detection is listed as a runtime solver responsibility, not only an admission check — ARCHITECTURE §3: 'a C++ engine owns all decision logic (constraints, modifiers, overrides, cycle detection, temporal validation) over the in-memory subgraph.' A hard-dependency cycle at solve time means neither node's support grounds out, so both Haber and Industrial Catalysis Research compute unrealized — and since both are current_truth and demonstrably existed, the TB-042(c) entailment-vs-fact contradiction detector fires automatically, surfacing a bounty that localizes exactly the bad pair. Failure mode = incompleteness + self-flagging diagnosis, never a false REALIZED — the prime-directive test (ADR-0015) passes. (2) ADR-0006's Consequences explicitly anticipates this content error: 'Getting it wrong either creates an illegal cycle (caught by the circuit breaker) or hides a real dependency' — the true fix is epistemic, not procedural: one edge is re-typed to OPTIMIZES (catalysis research OPTIMIZES Haber) via an ordinary forward edit (ADR-0031 §2), through normal review. No 'victim-selection algorithm' is needed because which edge is wrong is a factual question answered by moderation/challenges (ADR-0033), like any other good-faith error that clears review (same class as TB-043/044's accepted-then-repaired content). No Finding-3-style rollback is invoked. (3) The vouch-penalty 'misfire' is refuted: ADR-0013 §4 prices vouching for VANDALISM; six reviewers who endorsed individually-true, well-sourced edits committed no vandalism, so the rule simply does not fire — a coherent, defined outcome (reputation punishes bad faith and nonsense, while subtle factual errors flow through the challenge/demotion machinery; ADR-0029 §4 docks standing only for REJECTED edits). (4) The mass-orphaning analog is mitigated structurally: nothing is deleted (ADR-0011) and re-parenting routes through the Q-04 check queue with human confirmation; jointly 'orphaned' children degrade to magic-box/stub incompleteness under graceful ignorance, not wrongness. What is genuinely missing: the TOCTOU race itself is real — per-CR shadow-branch validation against a master lacking the sibling edge, plus ADR-0031 §2's deliberately conflict-free set-union apply, means a state the ADR-0013 breaker is 'defined to auto-reject' can enter master and is then detected only LAZILY (when someone queries either node and the TB-042 bounty lights up), and no TB case pins the eager path. The missing rule is small and precise: re-run the structural circuit breakers (cycle, orphan) against post-merge master — either as a serialized recheck inside the transactional apply (cheap in Postgres MVCC and non-destructive to merge commutativity: it flags, it doesn't reorder) or as part of the periodic skeleton-snapshot analytics ADR-0031 §3 already schedules for transitive-reduction linting — routing joint violations into the existing review queue as a flagged pair rather than an auto-rejected victim. Everything downstream of detection already exists.

## FINDING 10: Patient-zero rollback vs. a year of legitimate downstream work; dangling edge-ID leaves in requirement expressions
**Severity claimed:** high · **Verdict:** HANDLED

### Scenario
2027: a good-faith contributor adds 'Bessemer Process → ENABLES → Crucible Steel' from a misread secondary source (crucible steel actually predates Bessemer by a century). It passes review (plausibility trap), gets a citation, even clears L3 against the sloppy source. Over the next year ~300 legitimate edits build on it: downstream consumers author ADR-0017 requirement expression trees whose OR/AND leaves reference that edge's ID; the ADR-0021 linter shadows an older coarse edge as covered by a path through it; earliest-possible-date entailments shift. Then a historian catches patient zero and the community wants it rolled back.

### Claimed failure
Two accepted ADRs prescribe different revert models and neither defines the blast boundary: ADR-0011/ADR-0013 promise 'atomic rollback of graph sections' as the safety net, while ADR-0031 §2 says 'reverts are forward edits (OSM pattern)' — per-object and manual. No ADR computes WHICH of the 300 interleaved good-faith edits belong to the rolled-back 'section,' so atomic section rollback destroys legitimate work while a lone forward-edit revert leaves wreckage: ADR-0017 expression trees hold raw edge IDs as leaves, and the truth value of a leaf referencing an archived/rolled-back edge is explicitly undefined (tri-state semantics deferred to Phase 4 — 'defined then, not now'). An AND over a dangling leaf either computes the consumer unrealized (wrongness: the thing demonstrably exists) or silently drops the leaf (wrongness if load-bearing). ADR-0021 §4 only re-validates shadows when covering edges 'change' — archival-via-rollback is not in its trigger list. The prime directive demands failure modes produce incompleteness, never wrongness; the recovery path itself produces wrongness.

### Verifier adjudication (full)
The finding presumes the correction must be a 'rollback' with a computed blast boundary. It isn't, and the boundary question dissolves under the facts-only constitution. Walk-through: (1) The historian's fix is one forward edit — the Bessemer→Crucible edge's ValidityStatus flips to disproven / lifecycle archived with a DISPROVED_BY citation (ADR-0011 archive/deprecate lifecycle; ADR-0031 §2 reverts-as-forward-edits; ADR-0034 §5 'even corrections are new records'). Nothing else needs touching. (2) The 'two revert models' contradiction is illusory: in an append-only store, ADR-0011/0013's 'atomic rollback of graph sections' is mechanically a batch of forward supersessions — ADR-0034 §5 makes both records permanent ('we asserted X at T1; we retracted it at T2 both remain forever'). One storage semantics, two granularities: the section-rollback safety net is scoped in ADR-0013 to vandalism clusters, where the 'section' is the attacker's ChangeRequests identified by author/anomaly-cluster (the CR, not a graph region, is the rollback unit); a good-faith factual error is the OSM-style single forward edit. Different tools for different problems, not conflicting prescriptions for the same one. (3) The 300 downstream edits need no boundary computation because ADR-0026 forbids stored inference: earliest-possible dates, states, and conditionality are entailments recomputed at query time, so they self-heal the instant the validity fact lands — 'earliest-possible-date entailments shift' is the system working, not wreckage. Each downstream fact stands or falls on its own evidence; ADR-0032 §2 automatically demotes any claim resting on the sloppy source ('no cleanup crew, no stale confidence' — TB-044's retraction half is this exact shape). Which downstream content deserves human re-examination is found via the ADR-0011/0034 record-time provenance trail and triaged through the Q-04 check queue — TB-042(b) is the direct precedent: a disproven conjecture (patient zero) with hundreds of children, resolved by one validity flip + subtree-wide recomputation + check-queue salvage triage, marked Solved. (4) 'Dangling leaves': the leaf is never dangling because nothing is deleted (ADR-0011) — it references a real edge whose validity is now disproven. Requirement-expression evaluation over validity status is established machinery, not deferred: TB-041/TB-042 compute conditionality as 'does any path in the ADR-0017 expression avoid hypothetical/invalid support' (ADR-0017 + ADR-0026 + ADR-0027 validity-on-edges). An AND over a disproven leaf fails that path; if no path survives while the consumer is current_truth, the result is unrealized → bounty — which TB-042(c) explicitly defines as the productive missing-node detector ('the same bounty as iPhone has no path through battery'), i.e., incompleteness that localizes crucible steel's real missing parentage, not wrongness. The ADR-0017 Phase-4 deferral is specifically NOT-over-unknown tri-state, a different case. No mechanism 'silently drops' leaves. (5) ADR-0021 §4's operative trigger is the general condition 'covering edges change... such that coverage no longer holds' — archival/disproof of the covering edge is the paradigm case; date-bounded/excluded/shadowed are examples, and the record is declared 'derived metadata over immutable truth,' so under ADR-0026 §4 recomputation always wins a stale shadow. Even in the worst lag window there is no wrongness: ADR-0021 §3 has existence/truth queries treat shadowed edges as valid regardless — only counting/rendering could briefly under-report, an incompleteness. Every failure mode in the scenario lands on incompleteness-plus-bounty, exactly what ADR-0015 demands.
