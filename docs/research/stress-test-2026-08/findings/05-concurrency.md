## FINDING 17: Edge-level duplicate assertions under set-union; implicit-AND of the unreferenced twin
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
During a 10,000-agent battery-history sweep, two pipelines independently assert Lithium IS_INGREDIENT_OF Li-ion Battery (TB-019's edge) with different citations, justifications, and distinct edge UUIDs. The search-first existence check (Q-20/TB-032) queries MASTER — both CRs are simultaneously pending shadow branches, so neither sees the other, and ADR-0031's idempotency keys only dedupe retries by the same agent. Each CR is individually flawless; disjoint reviewer sets vouch both within the hour. Both merge.

### Claimed failure
ADR-0031's set-union is keyed by assertion identity (UUID), not content, so both edges land permanently: BOM/counting queries double-count lithium, and there is no healing path — ADR-0011's MIGRATED_TO redirect is node-level only (edges have identity but no merge lifecycle), deletion is forbidden, and ADR-0021 shadowing is defined for coarse-covered-by-fine, not identical twins: twins cover each other symmetrically, so which one gets shadowed is an arbitrary order-dependent choice, and ADR-0023's 'convergence up to merges' clause covers only node merges. Interaction kicker: if the consumer carries an ADR-0017 tree referencing one twin (Electronic Computer: OR(vacuum_tube, transistor_edge_A)), the unreferenced twin edge_B is implicitly ANDed in — Transistor silently becomes a hard requirement and ENIAC-in-1945 computes as impossible: the duplicate produces WRONGNESS (ADR-0015 violation), contradicting the load-bearing axiom that duplicates are merely incomplete. TESTBED covers node-level dedup (TB-032, TB-037) but no case or ADR addresses edge-level duplicates at all.

### Verifier adjudication (full)
The permanence/double-count half is refuted by composition. ADR-0021's shadow record is defined as 'the set of finer edges that fully cover its claim' — an identical twin fully covers its claim (identity is the degenerate case of coverage), and the ADR's background redundancy linter proposes exactly such marks through the normal review lane; parallel identical edges are its easiest case. The 'symmetric twins → arbitrary choice' objection fails ADR-0023 on its own terms: whichever twin is shadowed, counting queries skip one and the effective graph is identical — convergence is defined over effective graphs up to merges (ADR-0023 §3), and edges additionally have the full ADR-0011 lifecycle (edges are first-class entities; 'every entity carries version-control fields'; statuses ACTIVE/DEPRECATED/MERGED; 'queries must filter by lifecycle status'), so a healing path exists without deletion. Pre-heal, two identical true assertions with different citations are redundant truth — ADR-0021's exact category — and under ADR-0032/0033 the second citation actually strengthens the one claim. BUT the implicit-AND kicker survives every defense I constructed. Walk it: CR-A adds transistor_edge_A + tree OR(vacuum_tube, edge_A); CR-B (concurrent, so Q-20's master-only search misses A) adds duplicate edge_B with no tree — no version fork on the tree slot, so Finding-16's conflict routing never triggers; both apply cleanly. Master now evaluates OR(vt, A) AND B per ADR-0017's letter ('edges not referenced by an existing expression are implicitly ANDed in'), and ENIAC-1945 computes as impossible. Every STORED fact is true, but the entailment is false — and TB-041 establishes the design's own standard that reachable false entailments demand a rule (the hypothetical-validity rule was added precisely to block a false unlock), and ADR-0017 prizes monotonicity ('adding information only unlocks') which this violates without NOT. Mitigation exists — TB-042's entailment-vs-fact contradiction detector fires on the cited ENIAC realization and localizes the duplicate; shadow/lifecycle heals it — but the window is wrongness, not incompleteness, so ADR-0015's failure-mode test is not met by detection-plus-repair alone. The one missing rule, precisely: requirement-expression evaluation (including the implicit-AND default) must operate over claim-equivalence classes — an edge that duplicates, or is shadowed by, an edge already referenced in the expression is excluded from implicit-AND (equivalently: implicit-AND applies only to edges carrying a claim not already represented in the tree). With that one solver-semantics rule (a natural companion to ADR-0021's existing 'every query type must declare whether it reads shadowed edges' consequence), the entire finding collapses into already-handled redundant-truth machinery.

## FINDING 16: Singleton requirement-tree slot under commutative set-union (concurrent tree CRs; override races)
**Severity claimed:** high · **Verdict:** HANDLED

### Scenario
Catalytic Converter (TB-021's own example) has one hard edge to Platinum and no expression tree (default AND). Agent pipeline A, sweeping catalysis chemistry, opens a CR adding Palladium and Heat edges plus the tree OR(pt, AND(pd, heat)). Agent pipeline B, sweeping recycling tech, concurrently opens a CR adding a Rhodium-process edge plus the tree OR(pt, rhodium). Each CR is reviewed against master (which shows only Platinum), each is individually true, each collects its 3 vouches from different reviewers. Both merge the same day.

### Claimed failure
ADR-0031 defines CR-apply as commutative set-union of immutable assertions, but ADR-0017 allows exactly ONE tree per consumer node — the union contains two competing tree versions sharing one previous_version_id (ADR-0011). If versioning resolves last-writer-wins, the final graph depends on merge order, breaking the ADR-0023 pinned invariant; worse, the losing CR's edges are now unreferenced by the surviving tree, and ADR-0017's rule 'edges not referenced by an existing expression are implicitly ANDed in' promotes an OR-alternative (palladium AND heat) into a hard requirement — the graph asserts that platinum-only converters are impossible, a false statement violating ADR-0015 (wrongness, not incompleteness), which then falsely marks downstream consumers unrealized. ADR-0031's escape hatch 'true conflicts route to review' is silent on how same-slot tree writes are detected across CRs whose assertion sets are disjoint, defines no tree-merge semantics if they are, and a rebased/hand-merged tree is no longer the content the second CR's vouchers vouched for (ADR-0013 gives vouches no rebase semantics). The same singleton-slot race applies to ADR-0008/0019 overrides: two CRs widening the same inherited requirement to different, taxonomically incomparable LCAs (Mobile Processor vs RISC Processor) union into two RequirementOverrides on one original with no defined combination rule.

### Verifier adjudication (full)
The finding's failure chain requires two assumptions the design never makes: last-writer-wins fork resolution and partial CR application. (1) Detection: the requirement tree is a versioned entity (ADR-0017 puts it on the consumer node; ADR-0011 mandates version_uuid/previous_version_id on EVERY entity from day one). Two CRs writing trees against the same base produce two versions sharing one previous_version_id — a version fork, which is mechanically detectable at apply time and is the definitional 'true conflict' that ADR-0031 §2 explicitly routes to review ('true conflicts route to review'). The finding's claim that the CRs' assertion sets are disjoint is false at the version layer: both assert a successor version of the SAME entity slot. LWW is nowhere in the docs; the finding supplies it as a hypothetical and then attacks it. (2) No wrong intermediate state: CR apply is a transactional set-union (ADR-0031: Postgres/MVCC; ADR-0013: shadow branch merged as a unit), so the second CR's edges cannot land while its tree waits — the rhodium edge and the OR(pt, rhodium) tree are held together. Walking the scenario: CR-A merges; CR-B's apply detects the fork on the Catalytic Converter tree slot, does not apply, routes to review; master shows OR(pt, AND(pd, heat)) with rhodium merely absent — incompleteness, never the false 'platinum-only impossible' assertion. The implicit-AND promotion the finding fears requires the losing CR's edges to merge without its tree, which atomic apply forbids. (3) Resolution: ADR-0013 CRs are 'amendable by reviewers, merged only after approval' — a reviewer amends CR-B's tree to OR(pt, AND(pd, heat), rhodium) on top of current master and it merges only after approval of that content; nothing in any ADR transfers stale vouches onto amended content, so the 'vouches have no rebase semantics' objection attacks a mechanism (auto-merge of rebased content on old vouches) that doesn't exist — merged-only-after-approval IS the rebase semantics. ADR-0017 itself pre-answers the residue: 'mis-authored logic is ordinary editable content fixed by moderation, while the schema itself can always express the truth (ADR-0015).' (4) The override variant fails separately: RequirementOverride/InheritanceOverride records are accumulating justified facts, not a singleton slot. ADR-0019's effective-dependency formula ('own edges ∪ inherited edges − exclusions, with widenings applied') plus ADR-0026 (effective sets are computed entailments) means the solver applies ALL widenings; each widening only relaxes and is individually justified true (an x86 prototype AND a RISC prototype both exist), so the union of relaxations is commutative, order-independent, and never wrong — incomparable LCA targets just mean either subtree satisfies, refinable later to the common ancestor as an ordinary resolution increase (ADR-0008).

## FINDING 18: Vouch-threshold predicate over mutable reputation; slash/vouch interleaving; post-merge slash semantics
**Severity claimed:** medium · **Verdict:** HANDLED

### Scenario
An agent-authored CR adding an edge near Steam Engine (high dependency_mass) collects vouches from reviewers V1 and V2 on Monday. On Wednesday V1 is slashed to zero reputation for having vouched vandalism elsewhere (ADR-0013: 'vouching for vandalism costs the voucher reputation'). On Thursday V3 vouches — nominally the third vouch. In the racing case, V1's slash event and V3's vouch event arrive concurrently from different review queues.

### Claimed failure
ADR-0031 declares CR-apply commutative over immutable assertion sets, but the ADR-0013 merge precondition ('3 vouches') is a predicate over mutable reputation/vouch state, not over the assertion set — so the outcome depends on event interleaving: slash-before-third-vouch holds the CR; vouch-before-slash merges it. That is order-dependence inside the very machinery ADR-0023 pins as order-independent ('no future mechanism may break' the invariant), and no ADR defines the reconciliation: neither whether a slashed voucher's prior vouches are retroactively void, nor who un-merges an already-merged CR (ADR-0013 names 'atomic rollback' as a safety net with no trigger semantics; ADR-0031 says reverts are forward edits but nothing issues them on voucher-slash). ADR-0029 §4 deepens the race: agent vouches 'count only after accepted leaf contributions', and those acceptances are themselves concurrent CR merges — whether a vouch counts depends on the interleave of unrelated merges. Q-03 flags only tunable parameters (thresholds), not this time-of-check/time-of-use hole in the predicate itself.

### Verifier adjudication (full)
The finding conflates the admission gate with the apply operation and misreads the scope of the pinned invariant. (1) ADR-0023's invariant is explicitly 'any sequence of TRUE ADDITIONS converges to the same effective graph regardless of order' — it quantifies over insertion orders of accepted content, guaranteeing the graph is order-independent given the admitted fact set. ADR-0031's commutativity is likewise scoped to CR-APPLY ('whose apply is a commutative set-union of immutable assertions'). The vouch threshold is neither: it is the moderation gate deciding WHEN a CR is admitted (ADR-0013 layer 4). A gate whose outcome depends on evaluation time is how every review process works (a slashed-before-vouching V1 would equally hold the CR); it produces no divergent effective graph. Walk both interleaves: vouch-before-slash → the CR merges carrying content approved by three reviewers who were all in good standing when they vouched — the content's truth is unchanged by V1's later misconduct elsewhere; slash-before-vouch → the CR waits for one more vouch — pure incompleteness, and if the content is good it re-collects the third vouch and merges, so the admitted fact set converges anyway. Both branches satisfy ADR-0015's failure-mode test. (2) 'No defined post-merge semantics' is refuted on three documented axes: post-merge TRUST never rests on vouches at all — ADR-0032's verification ladder and ADR-0033's confidence are computed from citation/verification EVENT-FACTS, so a stale vouch leaves no false confidence standing (the same automatic-demotion principle as TB-044's retracted source); un-merging bad content has a named mechanism and trigger — reverts are forward edits (ADR-0031 §2, OSM pattern) issued through the same moderation loop that detected the vandalism, backed by ADR-0011/0013 atomic section rollback and 'patient zero' audit trails; and retroactively voiding a slashed voucher's unrelated vouches would REMOVE presumptively true content, which is why content-stands/voucher-pays is the reading consistent with ADR-0026 (facts stand on provenance, trust is computed). (3) The residuals the finding names — exact retro-void policy, and ADR-0029 §4 vesting-count timing — fall squarely inside the design's declared-open scope: Q-03 says the trust-chain mechanisms 'need concrete parameters, and the failure mode of each needs a story,' and TB-026 carries that open status; per the adjudication rules, ground already staked out in TESTBED/OPEN-QUESTIONS is a known tunable, not a break. Since neither policy choice can produce stored wrongness, the gap is parameterization, not architecture.
