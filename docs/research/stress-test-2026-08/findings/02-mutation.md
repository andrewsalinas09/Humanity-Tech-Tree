## FINDING 5: The Mobius merge: circular MIGRATED_TO redirects commit cleanly because redirects are invisible to every safety mechanism
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
ADR-0023's own example: Nokia's rubber era exists twice, as 'Finnish Rubber Works' (English-community authored) and 'Suomen Gummitehdas' (Finnish-community authored). A reviewer in each community independently files a ChangeRequest merging the OTHER node into 'their' canonical one. Both CRs are individually valid against master at branch time, get 3 vouches in their own language communities, and merge within the same hour. Result: A.migrated_to=B and B.migrated_to=A, both nodes lifecycle=MERGED. Every referrer now follows an infinite redirect loop; NEITHER node is canonical, so the entire rubber-era subtree (edges, citations, timelines) is stranded behind a cycle. The chained variant is as bad: A→B, later B→C, later C→A — each individual merge looks locally sane and no incremental check is defined to walk the redirect chain.

### Claimed failure
Three mechanisms interact to make this undetectable. (1) ADR-0028's migration table explicitly rules 'MIGRATED_TO: not an edge — node-level merge-redirect fact', so ADR-0013's cycle circuit breaker — defined over dependency edges — never sees redirect cycles. (2) ADR-0031 §2 defines CR conflict as 'base-version mismatch on a contested field'; the two merges write disjoint fields on different nodes, so commutative set-union applies both without routing to review. (3) ADR-0011 defines the redirect but no redirect-resolution semantics (follow-to-fixpoint? loop detection? which node is canonical when both are MERGED?) and no redirect-acyclicity invariant. TB-032/TB-037 assert duplicates 'heal via merge redirects' but no ADR defends the healing mechanism itself against concurrency. Resolution has NO defined answer, and the failure mode is total loss of access to a true subtree — worse than incompleteness.

### Verifier adjudication (full)
The mechanism gap is real, but the catastrophe claim fails. Walking the scenario: the finding is correct on all three enabling conditions — (1) ADR-0028's migration table rules 'MIGRATED_TO: not an edge — node-level merge-redirect fact', so ADR-0013's cycle circuit breaker (defined over dependency edges, 'except through OPTIMIZES') never inspects redirect chains; (2) ADR-0031 §2's conflict test is 'base-version mismatch on a contested field', and the two merge CRs write disjoint fields on different nodes (CR1 writes B.migrated_to/B.lifecycle, CR2 writes A.migrated_to/A.lifecycle), so commutative set-union applies both; (3) no ADR defines redirect-resolution semantics or a redirect-acyclicity invariant — I searched and found nothing. So the 2-cycle can commit. But the claimed failure mode — 'total loss of access to a true subtree, worse than incompleteness' — is refuted by the machinery that survives: nothing is deleted (ADR-0011), so every edge, citation, and timeline of the rubber-era subtree still physically points at A and B; the loss is only in a resolver that naively follows redirects without loop detection, and any resolver must already walk chains (A→B→C merges are expected in normal operation), making cycle detection a one-line addition, after which the cycle is DETECTED state, not lost data. Repair is fully covered by existing rules: reverts are forward edits (ADR-0031 §2, the OSM pattern) — a new version of A clearing migrated_to and restoring lifecycle=ACTIVE un-merges one side; record time (ADR-0034) plus author fields (ADR-0011) give the patient-zero audit showing exactly which two CRs collided. The state is a transient, mechanically detectable, mechanically repairable inconsistency — bounded incompleteness-of-canonicalization, not permanent wrongness. What is genuinely missing is one invariant, stated precisely: at CR-apply time, setting X.migrated_to=Y must walk Y's redirect chain to fixpoint and treat reaching X (or any already-MERGED node as target) as a true conflict routed to review — i.e., redirect-acyclicity joins cycles/orphaning/embedding as a fourth circuit breaker, and redirect resolution is defined as follow-to-fixpoint with cycle detection surfacing a repair bounty. This is exactly the shape of the existing ADR-0013 breakers (cheap structural check at merge time) and breaks no TB case; TB-032/TB-037's healing story stands once it exists. A missing check, not a broken architecture.

## FINDING 6: Un-merge does not exist: a wrong merge is standing, unrepairable wrongness — the one mutation whose failure mode the prime directive forbids
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
A reviewer merges 'Roman Concrete' into 'Pozzolanic Concrete' (defensible at the time — both are lime+pozzolana systems). Over the next 8 months, agents attach ~200 assertions to the canonical node: regional timelines, the lost/found knowledge segments from TB-004, consumer edges from Pantheon and Roman harbor works, citations at L3/L4, and a WIDEN override. Then 2033 hot-mixing scholarship establishes Roman concrete's self-healing mechanism is a distinct technology with a distinct dependency set (quicklime clast formation) — the merge was wrong; the graph currently asserts two different technologies are one. TB-032's own asymmetry note concedes this state is 'wrong', not 'incomplete'. Now try to undo it: ADR-0031's 'reverts are forward edits' can revert the redirect fact itself, but the 200 post-merge assertions were authored against the merged identity with no marker of WHICH pre-merge concept each one meant. Nothing can partition them.

### Claimed failure
ADR-0011 defines Merge, Deprecate, Archive — and no inverse for any of them; MIGRATED_TO has no defined un-merge operation. ADR-0011's 'atomic rollback of graph sections' cannot help because the post-merge assertions are not a section — they are interleaved with legitimate edits and individually ambiguous between two identities. ADR-0034's record time preserves every state forever but records no intent-attribution, so it reproduces the wrongness faithfully rather than resolving it. Q-04's check queue is scoped to re-parenting triage, not identity fission — no queue, verb (ADR-0012), or pipeline exists for splitting a node back into two. This directly contradicts ADR-0015 (wrongness must be inexpressible or repairable) and undercuts ADR-0023 §3, whose 'convergence up to merges' guarantee silently assumes merges are always correct. The architecture's entire duplicate-healing story rests on an irreversible operation applied by fallible reviewers.

### Verifier adjudication (full)
The finding's strongest word — 'unrepairable' — is refutable by composition of documented mechanisms; what it correctly identifies is that no ADR names the composed operation. Walking the repair: (1) Reopening both identities: 'reverts are forward edits' (ADR-0031 §2) — a new version of the Roman Concrete node clears migrated_to and restores lifecycle=ACTIVE; its entire pre-merge state survives verbatim in version history (ADR-0011), so nothing about the original identity must be reconstructed. (2) Partitioning the 200 post-merge assertions is NOT undefined-in-principle: record time (ADR-0034) cleanly separates pre-merge from post-merge assertions, and each post-merge assertion carries author + per-claim citations (ADR-0030), which is exactly the evidence a triage judgment needs. The triage pattern itself exists and is documented as REUSABLE: TB-042(b) applies 'the Q-04 pipeline reused verbatim' to a non-re-parenting job (which theorems survive on Weak Jacobian) — keep-or-move triage over an assertion set against two candidate homes is the same job here. (3) The finding's sharpest point — assertions 'individually ambiguous between two identities' — is answered by ADR-0008: an assertion genuinely true of both lime+pozzolana systems, or undecidable, parks at the Least Common Ancestor ('Pozzolanic lime system', created lazily), which is TRUE at lower resolution — the wrongness-to-incompleteness conversion the prime directive demands. Every assertion ends up somewhere true: clearly-Roman → reopened node, clearly-Pozzolanic → stays, ambiguous → LCA. Consumer edges from Pantheon re-point through the same triage; the WIDEN override was itself an LCA fact and survives at the parent. (4) The 8 months of standing wrongness is bounded by the same doctrine that governs TB-044's retracted source: the graph may assert something later refuted; as-of views label it as then-asserted (ADR-0034 §Why), and the architecture's real defense is the prevention asymmetry (TB-032/Q-20: never auto-merge, always err toward creating — duplicates are incomplete, wrong merges are wrong), which shows the design already prices merge as its most dangerous operation. So: not unrepairable, not a contradiction of ADR-0015's letter (wrongness inexpressible WHERE THE SCHEMA CAN ENFORCE it; identity distinctness is not schema-enforceable, so the obligation devolves to repairability, which the composition provides). But the finding is right that the composition is nowhere written down: ADR-0011 defines Merge with no inverse, no verb (ADR-0012) or queue performs identity fission, and the one pipeline it leans on (Q-04) is itself OPEN with 'pipeline unspecified'. ADR-0023 §3's 'convergence up to merges' does silently assume merge correctness. The precisely-named missing rule: an Un-merge/Split verb defined as (a) forward-edit reversal of the redirect reopening the merged node, (b) automatic enqueue of all record-time-post-merge assertions into the check-queue triage with three outcomes (keep / move / park-at-LCA), (c) LCA-parking as the mandatory ambiguity default so no assertion is ever forced into a possibly-false home. Every ingredient exists; the ADR gluing them does not.

## FINDING 7: Merging two family roots that both carry iteration records and version nodes
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
One contributor builds family root '802.11' (before marketing aliases were entered); another builds 'Wi-Fi'. Search-first misses the equivalence. Root A lifts 802.11n to a real version node (Significance: MIMO) with feature edges; root B holds 'WiFi 4 (802.11n)' as a ProductIteration record whose data disagrees with A (B's record says 40MHz channels arrived in n; A's edges say ac). Both roots also hold overlapping-but-conflicting records for 802.11j, TB-006-style feature-presence data, and their own version-node stars. Now merge: B MIGRATED_TO A. Referrer edges follow the redirect — but B's ProductIteration list is data INSIDE the node body (ADR-0009/0018), which no redirect semantics touches. Post-merge, 802.11n exists simultaneously as a version node under A and an iteration record in B(-now-merged); 'which versions have feature X' scans (the exact query TB-006/TB-033 were solved with) either miss B's records entirely or double-count n.

### Claimed failure
ADR-0011's merge mechanic is a node-level redirect; it defines behavior for referrers (edges) but is silent on node-internal payloads: ProductIteration lists, minor_examples, name_history, aliases with conflicting date claims. No ADR defines record-level dedup, record-vs-node reconciliation, or record conflict resolution — records are not per-claim assertions with citations the way edges are, so ADR-0032/0033 verification machinery can't even score the disagreement. ADR-0018 §4 declares lifting a 'monotone resolution increase', but a root merge creates the record+node coexistence state that monotonicity assumes impossible, with no defined winner. And ADR-0023 pins 'convergence is defined up to merges' as the order-independence invariant — but since the merge operation is undefined for record payloads, the post-merge state depends on which root a human picked as canonical and what they manually did with the records: order-dependence smuggled back in through the exact mechanism that was supposed to guarantee its absence.

### Verifier adjudication (full)
The BREAKS claims are refuted by composition. (1) No double-counting: ADR-0011's consequences mandate 'queries must filter by lifecycle status,' so post-merge the TB-006-style scan reads only canonical root A — B's ProductIteration records on the MERGED body are simply not surfaced. That is a MISS, i.e. labeled incompleteness, the explicitly legal failure mode (ADR-0015: 'failure modes may produce incompleteness, never wrongness'); nothing false is asserted in the interim state. (2) Monotonicity does not break: ADR-0018 §4's lifting (record → node/edges) applies unchanged when the target version node already exists — B's 'WiFi 4' record lifts into claims on A's 802.11n node, a monotone resolution increase; the residual record on the MERGED node is audit history under ADR-0011, not a competing truth carrier, exactly like an archived edge. (3) The 40MHz-in-n vs -in-ac disagreement becomes, once lifted, two ordinary per-claim cited assertions that ADR-0032 challenges and ADR-0033 scoring handle; pre-lift it is invisible (incomplete), not wrong. (4) Order-independence is not smuggled away: ADR-0023 §3 defines convergence explicitly 'up to merges' and §4's permutation test asserts identity of POST-merge effective graphs; once payload migration completes (alias union + records appended-or-lifted), the effective graph is identical regardless of which UUID survived — redirects erase the difference. The 802.11 worked example §6 already states node-worthiness mistakes are 'recoverable in both directions (create later + lift, or merge + redirect).' What IS genuinely missing, and why this is PARTIAL not HANDLED: ADR-0011 defines Merge only as a MIGRATED_TO referrer redirect; no document specifies merge-time payload semantics. The missing small rule: 'On MIGRATED_TO, node-body payloads migrate — aliases/name_history union onto the canonical node; each non-canonical iteration record enters a triage queue (the Q-04 LLM-proposes/human-confirms shape) where it is appended to the canonical record list or lifted via the ADR-0018 lifting verb into the existing version node, conflicts landing as ordinary contested per-claim facts; until processed, MERGED-node payloads are excluded from scans.' Note ADR-0018's consequences already flag the lifting operation as an undesigned edit verb, so this is a scoped extension of an acknowledged to-do, and its endpoint restores ADR-0023's invariant.

## FINDING 8: Override records pin computed graph shapes that routine surgery silently invalidates
**Severity claimed:** medium · **Verdict:** PARTIAL

### Scenario
Leg (a), the drifting LCA: per TB-017, the x86 prototype iPhone gets a RequirementOverride widening 'ARM Cortex' to the then-LCA 'Processor', with relaxed_target_id stored. Two years later a contributor doing DSP work performs ADR-0008's own recommended move — Abstract This — inserting 'Application Processor' between ARM/x86 and 'Processor'. The true LCA of the two implementations is now 'Application Processor', but the stored override still says 'Processor', so the solver accepts an 8051 microcontroller as satisfying the iPhone family requirement — an entailment the justification never supported, asserted as fact. Leg (b), the orphaned exclusion: a camera-less iPhone variant records EXCLUDE against family_edge_id of the generic 'iPhone → Camera' edge (TB-034 machinery). Then TB-035's specialization lands: front/rear camera edges are added at family granularity and the generic edge is shadowed (ADR-0020/0021). ADR-0019's effective-deps formula (own + inherited - exclusions) subtracts only the shadowed generic edge; the fresh front and rear family edges are inherited un-excluded — the instance whose camera-lessness IS RECORDED in the graph now renders with presumed front and rear cameras.

### Claimed failure
Both legs are the same disease: override records (ADR-0008's RequirementOverride.relaxed target, ADR-0019's InheritanceOverride.family_edge_id) freeze a reference to a computed or mutable graph shape, and no mechanism re-validates them when surgery changes that shape. Leg (a) additionally violates ADR-0026's litmus test outright — the relaxed target is a computed LCA, an ANSWER stored as a field, uncitable to any source; ADR-0026 calls exactly this 'future wrong information by time bomb', yet ADR-0008/0019 mandate storing it. Leg (b) is a one-directional re-validation gap: ADR-0021 §4 carefully re-validates shadows when covering edges change (even listing 'excluded' as a trigger), but nothing anywhere re-validates overrides when their referenced edges get shadowed, specialized, or date-bounded. The failure output in both legs is asserted wrongness (a satisfiable requirement that shouldn't be; presumed features on an instance recorded to lack them), not labeled incompleteness — and it is produced by composing three individually-Solved TESTBED cases (TB-017 + TB-034 + TB-035).

### Verifier adjudication (full)
Both legs' 'asserted wrongness' claims are refuted; a one-directional re-validation rule is genuinely missing. Leg (a): the relaxed target is not an ADR-0026 litmus violation — ADR-0026 §5 explicitly classifies justified editorial judgments as storable facts ('facts about human assessment'), and the widened claim 'iPhone family requires ≥Processor' is citable (evidenced by ARM and x86 members existing) and REMAINS TRUE after 'Application Processor' is inserted — it becomes non-minimal (coarse), not false, so there is no time bomb of the stored-inference kind. The solver accepting an 8051 is the TB-001/ADR-0003 class exactly: a technically-true path through a coarse requirement, the documented permissive-until-constrained behavior, classified as incompleteness and refined by tightening — never a false assertion (the graph never asserts an 8051 iPhone existed; 'satisfiable at current resolution' is a true entailment of true-but-coarse facts). The surgery moment even has a documented tripwire: Abstract This IS re-parenting (Glossary), which triggers the check queue (ARCHITECTURE §5); its pipeline is already OPEN as Q-04. Leg (b): the output is NOT asserted wrongness — ADR-0019 §3 renders inherited-unasserted facts as labeled presumptions ('incompleteness, never a false assertion'), so the camera-less instance shows dimmed presumed front/rear edges plus its recorded exclusion, a misleading-but-labeled state the prime directive tolerates. However, the finding correctly identifies the asymmetry: ADR-0021 §4 re-validates shadows when covering edges change, but nothing re-validates overrides when their referenced edge is shadowed/specialized or their relaxed target re-parented. The missing small rule (the mirror of ADR-0021 §4): 'Override re-validation — any Specialize/shadow event on an edge referenced by an InheritanceOverride's family_edge_id, and any re-parenting insertion below a RequirementOverride's relaxed target, queues that override for re-application at the new granularity (EXCLUDE propagates to the covering sub-role edges; WIDEN re-tightens toward the new LCA), via the existing linter-proposes/human-confirms lane.' Since the interim state is labeled incompleteness in both legs, the gap costs resolution, not truth — hence PARTIAL, not BREAKS.
