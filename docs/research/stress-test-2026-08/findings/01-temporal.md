## FINDING 1: The recalibration cascade — calibrated radiocarbon dates as stored entailments
**Severity claimed:** high · **Verdict:** PARTIAL

### Scenario
IntCal27 lands, superseding IntCal20 the way IntCal20 superseded IntCal13 in 2020 (which moved Iron Age and Neolithic dates by decades and re-dated the Hallstatt plateau). Thousands of nodes — first pottery per region, spread of agriculture, European megaliths, every RegionalAvailability TimeSegment start in prehistory — carry DatePoints whose `year` values are calibrated-under-the-old-curve numbers, each impeccably cited (L3/L4 verified) to pre-revision papers. Every one of those dates is now wrong by 20–150 years, and their relative order (which region got bronze first — the anti-Eurocentrism mechanism's core claim) may have flipped.

### Claimed failure
A calibrated ¹⁴C date is not a ground fact — it is an entailment of (raw lab measurement + calibration-curve version), but `DatePoint` (Node.cpp) stores only the final `year` double, and ADR-0026's litmus test ('could someone cite a source for this value?') passes it, so the facts-only constitution never notices it has admitted exactly the stored-inference time bomb ADR-0026 §Why warns about ('at billions of nodes nobody can find which ones'). Every automatic-repair mechanism misses: ADR-0032's instant demotion fires only on retraction facts, and the old papers are superseded, not retracted; ADR-0033 re-scores on formula changes, not on upstream-curve changes; ADR-0034 pins formula/verifier/embedding versions for as-of reproducibility but has no calibration-curve axis; and no stored fact links a DatePoint to the curve it rests on, so the affected set cannot even be queried. Bulk repair has no lane either — Q-07's bulk migration is about semantic repointing, not date revision. Result: mass wrongness (ADR-0015 violation) with no detector and no cleanup mechanism.

### Verifier adjudication (full)
Most of this finding refutes cleanly; one small automatic-demotion rule is genuinely missing. REFUTED, the constitutional charge: a calibrated date is NOT illegal stored inference under ADR-0026. The store holds facts about what sources assert ('paper P dates this stratum to 6200 BC'), and the litmus test is deliberately 'citable to a source' because the graph tracks the literature rather than re-deriving science — by the finding's logic every measured value in the graph (atomic weights, purity figures, ALL dates by any method) is an 'entailment of instrument + theory + calibration' and the store would be empty. ADR-0026's stored-inference ban targets the graph's OWN derived values (state, earliest-possible dates), which is why a bad answer 'always indicts the facts or the solver.' REFUTED, 'mass wrongness / ADR-0015 violation': the graph never asserts oracle truth — every date claim carries uncertainty_range (ADR-0027 §4), per-claim citations (ADR-0030 §5), a computed confidence with source trace (ADR-0033), and record time (ADR-0034). After IntCal27 the graph's state is 'claims cited to then-current sources' — being behind a moving literature is the graph missing new facts, i.e. incompleteness, the explicitly legal failure mode (ADR-0015). Repair is ordinary versioned editing (ADR-0011) at agent-swarm speed (ADR-0029), and ADR-0034 keeps the pre-revision assertions honest as history ('we asserted X at T1' remains true). REFUTED, 'the affected set cannot even be queried': overstated — TimeScale=ARCHAEOLOGICAL ('Dated by strata/carbon', Node.cpp:124) is a stored coarse handle, and wherever the curve IS cited, ADR-0033 §2 makes sources first-class nodes with claim→source edges, so 'claims resting on IntCal20' is exactly the queryable set TB-044 already exploits for retracted sources. Also, real calibrated prehistoric dates carry ±50–150yr ranges (the Hallstatt plateau is famous for exactly this), so many revised values remain inside their stored uncertainty — degraded resolution, not falsehood. WHAT GENUINELY IS MISSING (why not HANDLED): the design insists elsewhere that exactly this shape be AUTOMATIC — TB-044/ADR-0032 §2: 'a retraction fact instantly drops every claim resting on that source... no cleanup crew, no stale confidence.' But ADR-0032's event-fact list covers retraction, not supersession, and nothing requires the method-source (the calibration curve) to be recorded as a per-claim citation in the first place — so for curve supersession the detector the design promises for retractions simply never fires, and legacy claims lack the linking fact. The missing rule, precisely: (a) calibration-curve versions (and analogous method sources) are WORK_PUBLICATION source nodes cited per dependent date claim (authoring/ingestion convention — already legal under ADR-0033 §2, just not required); (b) ADR-0032 §2's automatic-demotion event set extends from 'retraction' to 'supersession' facts on source nodes, so an IntCal20-superseded fact demotes confidence on every claim citing it, turning the whole cascade into the standing decomposition/repair bounty machinery (ADR-0033 §5). This is the TB-044 pattern generalized one word — small, compatible, and genuinely absent today.

## FINDING 3: Plain-> over intervals — MAX and anachronism checks with overlapping uncertainty ranges
**Severity claimed:** medium · **Verdict:** PARTIAL

### Scenario
Earliest-possible date for 'geared astronomical calculator' = MAX over hard deps including 'differential gearing', dated -150 ± 100; the Antikythera mechanism artifact node is dated -100 ± 50 (wreck cargo vs letter-form dating — real ranges overlap). Does temporal validation (an explicit C++ engine duty per ADR-0010) flag artifact-predates-dependency because -100 < -150+... or pass it because the intervals overlap? Now mix scales in one chain, which any first-principles derivation (signature query #1) does: 'controlled fire' at -400,000 ± 300,000 (GEOLOGICAL) sits under HISTORICAL nodes dated to the half-year — the chain's earliest-possible answer is reported as one crisp decimal year whose real error is ± 300 millennia.

### Claimed failure
Every date mechanism is defined on scalar decimal years — TB-007's ordering is 'plain >' (the digest that deleted FuzzyTime says so verbatim), and ARCHITECTURE §6 / ADR-0025 define earliest-possible as 'MAX over hard deps' — while TB-008 made DatePoints intervals. No ADR says how MAX or < treats `uncertainty_range`: point-vs-point, pessimistic bound, or distribution. The two solved cases interact badly: with point comparison, a consumer at -1750 whose dependency is -1800 ± 200 falsely PASSES or FAILS depending on which side the point lands, and a failure feeds TB-042's missing-node detector — the contradiction-as-bounty mechanic fires a public bounty on a chain that is temporally fine, or stays silent on a real anachronism (KNOWLEDGE_REQUIREMENT person-predates-knowledge checks, ADR-0007/0025 §3, inherit the same undefined comparison). ADR-0026 makes this worse, not better: the answer is computed fresh every query, so the wrongness is systematic and untraceable to any storable fix.

### Verifier adjudication (full)
Partially refuted, but the comparison rule itself is genuinely unwritten. WHAT THE FINDING GETS WRONG: (1) The 'untraceable to any storable fix' conclusion inverts ADR-0026's actual dividend. Because earliest-possible dates and temporal checks are entailments computed fresh (ADR-0025 §5, ADR-0002), a naive point-comparison solver is ONE bug in ONE place: fix the C++ comparison, and every answer in the graph is instantly correct with zero migration — the exact opposite of the stored-inference time bomb; ADR-0033 §3 already demonstrates this pattern ('a formula change instantly re-scores the entire graph'). (2) No wrongness can be STORED: TB-008's answer preserves uncertainty_range + TimeScale on every DatePoint, so the facts are sufficient to compute the right answer forever — the prime directive's schema-level guarantee ('any state the graph can be in is true') holds; what can misfire is solver output, and ADR-0025 §6 makes bad entailments first-class diagnosable objects ('an absurd answer is a diagnosis... absurd traces are flaggable and feed the bounty loop'). A TB-042 bounty fired on a temporally-fine chain is a flaggable absurd trace pointing at the solver, not a stored falsehood. (3) ADR-0015 does not leave the semantics free — it uniquely DETERMINES it: any check that flags an overlapping-interval chain asserts a violation that may not exist (wrongness), so the only constitution-compliant rule is certain-violation-only — flag artifact-predates-dependency only when the intervals are disjoint in the violating direction (artifact.year + range < dep.year − range); overlap = consistent = pass. The Antikythera case (-100 ± 50 vs -150 ± 100, overlapping) therefore passes under the only legal reading, and KNOWLEDGE_REQUIREMENT person-predates-knowledge checks (ADR-0025 §3) inherit the same forced answer. Likewise the mixed-scale chain: reporting MAX(fire at -400000 ± 300000, ...) as a bare decimal is exactly the false precision ADR-0033 §4 already outlaws for confidence ('bands + trace, never a naked number') — the design's display ethos determines the answer (propagate intervals, report with TimeScale-appropriate bands). WHAT IS GENUINELY MISSING (why not HANDLED): none of that is written down. TB-007's record says comparison is 'plain >' verbatim; ADR-0010 assigns 'temporal validation' to the engine without semantics; ADR-0025 defines earliest-possible as MAX without saying MAX over what representation; and — by the project's own TB-030 standard that every edge case gets a TESTBED entry the moment it's raised — interval-overlap comparison appears in neither TESTBED.md nor OPEN-QUESTIONS.md. The forced-by-ADR-0015 argument is my derivation, not a documented mechanism, and the interaction the finding identifies (undefined comparison feeding TB-042's automated bounty) is a real composition hazard until specified. The missing rule, precisely: a temporal-semantics ADR (or TB entry + Q-ID) stating (a) all temporal consistency checks fire only on certain violation — intervals disjoint in the violating direction; overlap passes (monotone-safe: incompleteness, never a false flag); (b) derived dates (MAX over hard deps, ADR-0025) propagate via interval arithmetic — the result is an interval whose scale is the coarsest contributing TimeScale, never a bare scalar; (c) TB-042's contradiction detector consumes only certain violations. Small, forced by existing principles, and absent.

## FINDING 4: Timeline coherence is unenforced: overlapping ACTIVE/LOST segments and free-string regions give computed state two answers
**Severity claimed:** medium · **Verdict:** PARTIAL

### Scenario
Roman concrete — TB-004's own poster child — says geo:europe: LOST 476–1414. A Byzantinist contributor, correctly, adds geo:byzantine-empire: ACTIVE 476–1204 (Hagia Sophia's pozzolanic mortar, 537 AD). Query: state of Roman concrete in Constantinople, 800 AD — Constantinople is inside both region strings. Separately, within ONE region slug: contributor A ends Europe's Lost segment at 1414 (Palladio-era rediscovery); contributor B appends ACTIVE from 1300 (Italian maritime mortar); ADR-0011 forbids deleting either, so geo:europe's Timeline now contains LOST and ACTIVE segments both covering 1300–1414.

### Claimed failure
`Timeline` is a bare vector<TimeSegment> (Node.cpp) with no non-overlap invariant, no ADR defines precedence between contradictory segments, and `historical_region` is a free string with no containment hierarchy — so ADR-0002's computed state, the 'from (Time + Location + Node)' query that the entire buildability/musket-in-1300 machinery rests on, returns LOST and ACTIVE simultaneously for one (time, place) with NO defined answer. Nothing catches it entering: ADR-0013's circuit breakers check cycles, orphaning, and embedding distance — not timeline coherence — and both contributors' segments are individually true, so this isn't vandalism. Worst, it breaks ADR-0023's pinned invariant from inside: insertion order independently converges, but converges to a graph whose state query is nondeterministic — 'the same effective graph' is not well-defined when the effective state function it induces is multivalued, and computed-not-stored (ADR-0026) means the contradiction reappears on every query rather than ever being resolvable as a fact.

### Verifier adjudication (full)
Most of this finding dissolves on a careful walk-through, but one solver rule is genuinely unwritten. Refutations first. (1) The cross-region half is not a contradiction under the documented model. historical_region is an opaque slug (Node.cpp RegionalAvailability); no mechanism anywhere performs containment inference, so the system never computes a state for 'Constantinople' at all — it computes state per region slug (ADR-0002: from Time + Location + Node against regional timelines). Query geo:europe → LOST; query geo:byzantine-empire → ACTIVE. Those are two different queries about two different citable ground facts (ADR-0026), both true at their own resolution. Under the project's explicit resolution doctrine (ADR-0003 'truth never changes, resolution increases'; the ADR-0033/TB-045 decomposition-bounty pattern), the coarse Lost-in-Europe claim coexisting with a finer Byzantine-Active claim is the anti-Eurocentrism mechanism working as designed — the Byzantinist's edit is a resolution increase, not a contradiction. The 'two answers for one (time, place)' failure requires containment machinery the architecture deliberately does not have; you cannot break a derivation the solver never performs. (2) The intra-region half misreads ADR-0011. 'Nothing is deleted' means history is versioned (version_uuid/previous_version_id) — it does not freeze the current state. Contributor A's end-date change is an ordinary forward edit creating a new version; the old segment lives in version history, not the effective timeline. The overlap only arises from CONCURRENT CRs, and there ADR-0031 §2 plausibly fires: both CRs write the same field (RegionalAvailability.local_timeline of the same node, per the Node.cpp struct) → base-version mismatch on a contested field → routed to review, not auto-unioned. (3) The ADR-0023 breakage claim is wrong outright: the pinned invariant is over the effective FACT set, and the fact set converges identically under any order. Whether the induced state function is single-valued is a solver-semantics question, not a convergence break. What is genuinely missing: no ADR defines how the buildability query (ARCHITECTURE §6, 'intersected with regional timelines') evaluates when a region slug's timeline contains overlapping ACTIVE and LOST segments — which CAN legitimately occur post-review, because 'active in maritime Italy' and 'lost in most of Europe' are simultaneously true of the coarse slug. The missing rule is small and consistent with everything else: (a) state queries evaluate against exactly one region slug, never via inferred containment; (b) within a slug, overlapping segments compose existentially — an ACTIVE segment satisfies buildability (known somewhere in the region), LOST blocks only when no ACTIVE segment covers the instant; (c) an ACTIVE/LOST overlap is flagged as a region-decomposition bounty (the TB-045 move applied to geography). One paragraph in an ADR closes this; no schema change needed. Also worth recording: ADR-0031's CR-conflict granularity for timeline segments (segment-as-assertion vs timeline-as-field) should be pinned to the field level so the concurrent case reliably routes to review.

## FINDING 2: Bimodal disputed dates — Thera's two-camp century-wide dispute
**Severity claimed:** high · **Verdict:** HANDLED

### Scenario
The Thera/Santorini eruption: the radiocarbon-and-dendrochronology community dates it ~1627–1600 BC; Egyptian-chronology archaeologists date it ~1540–1500 BC — a century-wide, genuinely two-camp dispute that anchors the entire Aegean Late Bronze Age, so dozens of Minoan/Mycenaean technology nodes and TimeSegment transitions date relative to it. A contributor must now fill in the eruption's DatePoint (it is a `transition_reason` and an ENABLES start date for downstream nodes). Same shape at 500-year scale: the Kensington Runestone (1362 by inscription vs ~1890 by scholarship) or early Iron Age chronologies of the southern Levant (high vs low chronology).

### Claimed failure
ADR-0027 §4 rules 'date confidence stays numeric (`uncertainty_range`); the ConfidenceLevel enum stays dead' — so the only legal encoding is one DatePoint ≈ -1560 ± 60, a unimodal blur whose center is a date NO community asserts. That is precisely the move ADR-0015 forbids ('uncertain content must be stored as uncertain rather than rounded to a clean false claim') — a bimodal dispute rounded to a clean false midpoint. The escape hatch contradicts another mechanism: encoding the two camps as two dated edges collides with ARCHITECTURE §1's 'multiple active periods = multiple edges', which the solver must read as two occurrences, not one disputed occurrence. And the dispute machinery can't reach the date: EpistemicStatus lives on edges (ADR-0027 §3) and ADR-0033 confidence attaches per-claim, but a DatePoint is a *field inside* an edge/TimeSegment, not a claim that can carry competing values with per-camp citations. TB-008 solved dating *textures*; no mechanism stores competing date facts about one event.

### Verifier adjudication (full)
The finding's central claim — 'the only legal encoding is one DatePoint at a midpoint nobody asserts' — is false; three documented mechanisms compose to cover it. FIRST, the direct precedent the finding overlooks: TB-009 IS the mechanism for competing claims about one event stored simultaneously. 'Aliens built the pyramids' and 'Egyptians built the pyramids' are two parallel edges on the same event, each with its own EpistemicStatus and citations, ALL stored, filtered at view time (ADR-0027 §3: 'ALL truth levels are stored, users filter at view time'). Thera is the same shape with both camps at epistemic=debated: two parallel dated edges, one carrying start ≈ -1613 ± 14 cited to the radiocarbon/dendro literature, one carrying ≈ -1520 ± 20 cited to the Egyptian-synchronism literature. Each is a per-claim citable unit — ADR-0030 §5 and ADR-0032 §3 say explicitly that 'nodes, edges, and regional claims EACH carry their own sources/level,' so the dispute machinery reaches the date via the edge that carries it; no new claim-granularity is needed. SECOND, the claimed collision with 'multiple active periods = multiple edges' dissolves under ADR-0017: the consumer's requirement expression disambiguates. Two co-required periods are ANDed (the default); two disputed alternatives are OR(edge_high_chronology, edge_low_chronology) — TB-021's exact machinery ('a requirement satisfied by alternatives'), and the epistemic=debated marking on both edges tells any reader which situation it is. Even the lazy-authoring failure mode is safe in the ADR-0017 direction: a missing OR makes requirements stricter (over-constrained → possibly unrealized → bounty), never a false unlock — the monotone-incompleteness story, not wrongness. THIRD, the midpoint-blur the finding fears is caught by two independent nets even if a contributor authors it: a DatePoint of -1560 ± 60 cited to sources that assert no such value dies at the L2→L3 machine-verification gate (ADR-0032 — the verifier fetches the source and finds it does not support the claim), and a wide contested date on a famous event is the canonical ADR-0033 §5 decomposition bounty (TB-045 verbatim: 'a low score on a popular claim splits into finer facts that each score well' — here, the two per-camp claims, each high-confidence facts about what each community asserts). Note also that the maximally-lazy encoding '-1565 ± 65' (between 1630 and 1500 BC) is not a 'clean false claim' — the eruption genuinely occurred in that window, so it is true-at-low-resolution, exactly what ADR-0015 legalizes; the bimodal texture is then recovered by decomposition, the design's universal resolution-increase move. ADR-0027 §4 forbids only the ConfidenceLevel ENUM on DatePoint; it nowhere forbids parallel competing dated claims. The residual — no ADR spells out 'disputed date = parallel per-camp edges joined by OR, never averaged' as a named authoring idiom, and Q-14's dispute-resolution WORKFLOW is open — is a documentation/workflow gap, not a storage-encoding gap: every mechanism required already exists and composes without modification, which is the definition of HANDLED here.
